robotframework-what-it-is || Robot Framework: automação genérica com sintaxe de texto puro || O README oficial descreve o Robot Framework como um framework genérico de automação em código aberto para testes de aceitação, acceptance test driven development (ATDD) e automação de processos robóticos (RPA), com sintaxe simples em texto puro e extensível por bibliotecas genéricas e customizadas. || Para times que precisam de casos de teste legíveis por quem não programa, a sintaxe de texto puro reduz a barreira de entrada; e como o framework é independente de sistema operacional e de aplicação, o mesmo caso serve para web, API e desktop via bibliotecas. || A linguagem de alto nível usa palavras-chave com argumentos; a lógica reutilizável mora em bibliotecas (o Python é a linguagem primária de extensão), e o ecossistema de bibliotecas e ferramentas genéricas vive em projetos separados do núcleo. || Escreva um caso de teste como uma sequência de palavras-chave, por exemplo "Input Username    demo", e importe a implementação de uma biblioteca ou resource file; o framework cuida da execução, da logagem e do relatório. || O README não define uma API de asserção embutida: as palavras-chave concretas (browser, HTTP, banco) vêm do ecossistema, cuja qualidade e licença podem variar por projeto. || Conferi a definição, os três usos declarados e o modelo de extensão no topo do README oficial do repositório robotframework/robotframework. || rfr_readme,rfr_repo || O README descreve o propósito do framework e sua natureza extensível.
robotframework-install-python-versions || Instalação por pip e a escada de versões do Python || A instalação oficial é "pip install robotframework" com Python e pip já presentes; o framework exige Python 3.8 ou mais novo, roda também sobre PyPy, e downloads oficiais são hospedados no PyPI. || Projetos legados precisam saber exatamente até que versão subir: o README aponta Robot Framework 6.1.1 como a última com suporte a Python 3.6 e 3.7, e Robot Framework 4.1.3 para quem ainda depende de Python 2, Jython ou IronPython. || Instale no ambiente virtual do projeto, confirme "robot --version" e, se a ferramenta exigir Python 2 ou interpretes alternativos, fixe explicitamente a tag 6.1.1 ou 4.1.3 no pip em vez de esperar que a linha principal suporte esse ambiente. || pip install robotframework; para um CI antigo em Python 3.7, pip install robotframework==6.1.1; para Jython, pip install robotframework==4.1.3. || O suporte a Jython/IronPython existe apenas nas linhas antigas (4.1.3); a versão atual não oferece isso, e o README documenta esses pins como a saída para quem não pode subir o Python. || Conferi o comando de instalação, o requisito Python 3.8+, o suporte a PyPy e os pins 6.1.1/4.1.3 na seção Installation do README oficial. || rfr_readme,rfr_repo || O README lista requisitos de Python e as versões de transição.
robotframework-suite-syntax || A anatomia de uma suíte: tabelas Settings e Test Cases || O exemplo canônico do README mostra o formato de arquivo: seções demarcadas por "*** Settings ***" e "*** Test Cases ***", documentação multi-linha continuada com "...", importação de "Resource    login.resource" e testes definidos como nomes de caso seguidos de palavras-chave com argumentos. || Essa sintaxe em tabela é a interface entre análise e engenharia: o mesmo arquivo pode ser lido por leigos e executado pelo robot; entender as seções é o primeiro passo para estruturar suítes grandes sem transformar tudo em script. || Declare configurações e imports na seção Settings, defina cada caso de teste como um título seguido de linhas de palavras-chave, e mova fluxos reutilizáveis para um resource file importado, como o exemplo faz com a resource de login. || *** Test Cases ***   Valid Login: Open Browser To Login Page; Input Username    demo; Input Password    mode; Submit Credentials; Welcome Page Should Be Open; [Teardown]    Close Browser — exatamente o caso "login válido" do README. || O README observa que a sequência de palavras-chave "Input Password    mode" é o fluxo do exemplo (não um erro de digitação oficial); o valor do argumento é o que o exemplo define, e casos reais precisam de dados consistentes com o sistema testado. || Copiei o exemplo "Valid Login" linha a linha do README, inclusive a continuação "..." da Documentation e o [Teardown] final. || rfr_readme,rfr_repo || O exemplo completo de suíte vem literalmente do README oficial.
robotframework-robot-cli || Execução pela linha de comando: robot, variáveis e outputdir || O README define a execução pelo comando "robot" (ou "python -m robot"), passando o caminho de um arquivo ou diretório de testes como argumento, com opções de linha de comando antes do caminho — o exemplo oficial usa --variable BROWSER:Firefox e --outputdir results. || Colocar as opções antes do caminho não é capricho estético: variáveis como BROWSER parametrizam o mesmo suíte contra Firefox ou Chrome, e --outputdir organiza artefatos (log, relatório, xunit) para o CI coletar sem glob improvisado. || Execute "robot tests.robot" para um arquivo único, "robot --variable BROWSER:Firefox --outputdir results path/to/tests/" para um diretório parametrizado, e recorra a "robot --help" para a lista completa de opções. || No CI, um passo "robot --outputdir results --variable BROWSER:Firefox acceptance/" gera os resultados em results/ e permite publicar só essa pasta como artefato. || O README documenta o formato básico; a referência completa de opções está no User Guide, que é o manual citado como documento de linha de comando. || Executei "robot --help" e comparei as duas linhas de exemplo da seção Usage do README. || rfr_readme,rfr_repo || A seção Usage do README oficial define o contrato da linha de comando.
robotframework-rebot || rebot: pós-processamento e junção de resultados || Junto com o robot, o projeto distribui o "rebot", ferramenta para combinar resultados e fazer pós-processamento — o exemplo do roda "rebot --name Example output1.xml output2.xml", e "rebot --help" traz a documentação da linha de comando. || Suítes executadas em paralelo ou em máquinas diferentes produzem output.xml separados; sem o rebot, o time precisaria manter um relatório por executador, e a visão única de falhas — que é o que a triagem consome — se perde. || Gere output.xml por partição (por shard, plataforma ou navegador) e rode rebot sobre os XMLs, dando um nome ao agregado com --name; o rebot relança log e relatório HTML a partir dos dados combinados sem reexecutar nada. || Duas execuções em paralelo geram shard1/output.xml e shard2/output.xml; "rebot --name Integration shard1/output.xml shard2/output.xml" produz o relatório único que vai para a página de artefatos do CI. || O rebot trabalha sobre os arquivos de saída existentes; ele não reexecuta testes nem reconstrói dados que não foram gravados, e o README remete ao User Guide para o comportamento completo. || Reproduzi o comando de exemplo da seção Usage do README oficial contra dois output.xml gerados por execuções locais. || rfr_readme,rfr_repo || O rebot e seu exemplo aparecem na seção Usage do README.

robotframework-ecosystem || O ecossistema como parte do produto || O README descreve um "rich ecosystem" de bibliotecas e ferramentas genéricas desenvolvidas como projetos separados, aponta para http://robotframework.org como a porta de entrada desse ecossistema e convida contribuições tanto ao núcleo quanto às ferramentas ao redor. || No Robot Framework, quase todo poder prático (browser, banco, SSH, REST) vem de bibliotecas de ecossistema; avaliar o framework sem avaliar a saúde das bibliotecas necessárias ao seu domínio é decidir no escuro. || Antes de adotar, liste as integrações de que o time precisa, localize-as no site do ecossistema, avalie atividade e mantenedor de cada projeto e trate-as como dependências com política própria de atualização. || O exemplo do README usa palavras-chave como "Open Browser To Login Page" que pressupõem uma biblioteca de browser; no ecossistema oficial, SeleniumLibrary e Browser são os caminhos típicos para essa capacidade. || Repositórios de ecossistema têm licenças, ciclos de release e políticas de suporte próprios — o README explicita que "they may use different licenses"; nada no núcleo garante SLA de terceiros. || O README indica o site do ecossistema e a nota de projetos separados; os exemplos de bibliotecas de browser são prática comum que o próprio site do projeto divulga. || rfr_readme,rfr_repo || A descrição do ecossistema vem das seções Introduction e Contributing do README.
