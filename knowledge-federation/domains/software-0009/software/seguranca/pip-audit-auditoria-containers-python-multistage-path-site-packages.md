# Auditando **Containers Python Distroless e Multi-Stage Builds** com `pip-audit`: Usando a Flag **`--path` (`site-packages`)** sem Instalar o `pip-audit` na Imagem Final

## Em uma frase
Nas melhores práticas de segurança de containers Python em produção, a imagem final de runtime (ex.: uma imagem **Distroless Python** ou um segundo estágio `python:3.12-slim`) contém **apenas o interpretador Python e a pasta `/app/.venv/lib/python3.12/site-packages` copiada do estágio de build (`builder`)** — ela não tem `pip`, não tem compiladores e não tem o `pip-audit` instalado dentro dela!

## Por que importa
Como usar o `pip-audit` do estágio de build (ou do host do runner de CI) para auditar exclusivamente os pacotes instalados dentro da pasta `site-packages` do container alvo sem poluir a imagem final de produção?

## Como funciona
Usando a flag oficial **`--path <CAMINHO_SITE_PACKAGES>`** combinada com **`--local`**! Quando você passa **`pip-audit --path /target/venv/lib/python3.12/site-packages`** (que pode ser repetida múltiplas vezes!), o `pip-audit` ignora os pacotes do próprio ambiente onde ele está rodando e audita **exclusivamente os metadados `.dist-info` contidos no diretório `--path` informado**!

## Exemplo
```bash
# Auditar um diretorio site-packages isolado (ex.: estagio final de um container multi-stage ou rootfs montado) usando --path no pip-audit
pip-audit \
  --path /app/.venv/lib/python3.12/site-packages \
  --strict \
  --aliases \
  -f cyclonedx-json -o ./container-python-sbom.json
```

## Limites e trade-offs
Olhe que padrão limpo para o seu `Dockerfile` multi-stage ou pipeline de CI: **(1)** O estágio `builder` instala as dependências da aplicação em `/app/.venv`; **(2)** O `pip-audit` instalado fora de `/app/.venv` roda `pip-audit --path /app/.venv/lib/python3.12/site-packages --strict` (falhando o build se houver qualquer CVE e gerando o SBOM CycloneDX!); e **(3)** O estágio final `runtime` faz `COPY --from=builder /app/.venv /app/.venv`, produzindo uma imagem de produção enxuta, 100% auditada e sem ferramentas extras de build!
