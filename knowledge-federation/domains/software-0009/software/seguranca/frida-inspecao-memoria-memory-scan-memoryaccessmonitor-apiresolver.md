# Frida: Varredura de Memória em Tempo Real (`Memory.scan`, `Process.enumerateRanges`), **`MemoryAccessMonitor`** e **`ApiResolver`**

## Em uma frase
As APIs **`Process.enumerateRanges(protection)`**, **`Memory.scan(address, size, pattern, callbacks)`**, **`MemoryAccessMonitor`** e **`ApiResolver`** permitem pesquisar padrões binários, chaves e strings na memória RAM viva do processo e armar armadilhas de página de memória.

## Por que importa
Diferente de um dump de memória estático, o **`MemoryAccessMonitor.enable(ranges, callbacks)`** monitora páginas de memória específicas e dispara o callback `onAccess(details)` no exato instante em que uma instrução lê, escreve ou executa (`read`, `write`, `execute`) aquele endereço (`details.from` informa o endereço da instrução que tocou na memória!).

## Como funciona
Já a classe **`ApiResolver("module")`** (ou `"objc"` / `"swift"`) resolve funções por padrões curinga (`exports:*!open*`, `imports:program.exe!*Crypt*`), mesmo quando você não sabe em qual biblioteca compartilhada a função reside.

## Exemplo
```javascript
// Localizar funcoes de criptografia em todos os modulos carregados usando ApiResolver com curingas
const resolver = new ApiResolver("module");
const matches = resolver.enumerateMatches("exports:*!EVP_EncryptInit*");
for (const m of matches) {
    console.log("[ApiResolver] Encontrado: " + m.name + " @ " + m.address);
}
```

## Limites e trade-offs
Ao usar `Memory.scan` percorrendo todas as regiões retornadas por `Process.enumerateRanges('r--')`, filtre regiões com nomes de dispositivos mapeados em `/dev/` para evitar leituras bloqueantes.

## Como verificar
Teste o `ApiResolver` acima em um processo que carrega `libcrypto` e confirme a resolução dos símbolos `EVP_EncryptInit_ex`.
