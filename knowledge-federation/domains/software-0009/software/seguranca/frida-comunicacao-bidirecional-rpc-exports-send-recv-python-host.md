# Frida: Comunicação Bidirecional Host-Agente (`send`/`recv`) e Exposição de Funções Internas como **API RPC (`rpc.exports`)** em Python

## Em uma frase
Um dos recursos mais poderosos do Frida para automação de pentests e fuzzing de protocolos proprietários é o **`rpc.exports`**: o script JavaScript injetado dentro do aplicativo expõe qualquer função interna do binário como um método Python (`script.exports_sync.<metodo>(...)`) que pode ser chamado diretamente do seu computador ou de uma extensão do Burp Suite / ZAP / `sqlmap`!

## Por que importa
Imagine um aplicativo mobile bancário ou cliente grosso que cifra o corpo JSON de cada requisição usando uma biblioteca C++ ofuscada com chaves derivadas de hardware: em vez de gastar duas semanas fazendo engenharia reversa da biblioteca C++ para reimplementar a criptografia em Python, o `rpc.exports` simplesmente chama a própria função de criptografia original dentro do aplicativo ao vivo!

## Como funciona
O script Python host carrega o agente via `session.create_script(js_code)`, registra um handler `script.on('message', on_message)` e invoca `script.exports_sync.sign_payload(raw_json)` de forma síncrona ou assíncrona.

## Exemplo
```python
import frida

JS_AGENT = """
rpc.exports = {
    getProcessInfo() {
        return { pid: Process.id, arch: Process.arch, platform: Process.platform };
    }
};
"""

session = frida.attach("cat")
script = session.create_script(JS_AGENT)
script.load()
print(script.exports_sync.get_process_info())
session.detach()
```

## Limites e trade-offs
Note que a versão moderna do binding Python do Frida converte automaticamente nomes `camelCase` definidos no JavaScript (`getProcessInfo`) para `snake_case` no atributo Python **`script.exports_sync.get_process_info()`**.

## Como verificar
Integre `script.exports_sync` a um script de pré-processamento do ZAP/Nuclei/sqlmap quando precisar assinar payloads de teste com a rotina criptográfica nativa do cliente.
