# ___FILE___: o contrato do input por arquivo

## Em uma frase
No modo clássico, o README define o calling convention com um placeholder explícito: "honggfuzz -i input_dir/ -- ./my_target ___FILE___", anotando que "___FILE___ is a placeholder for the input filename generated by honggfuzz".

## Por que importa
O contrato do nome do arquivo é o ponto em que o alvo se conecta ao motor: o programa fuzzado recebe um caminho, lê o conteúdo e processa — quem entende isso escreve alvos corretos de primeira, sem pipelines ad-hoc de stdin que quebram com corpora em disco.

## Como funciona
Escreva o main do alvo aceitando um argumento de arquivo (o caso mais simples é abrir argv[1] e parsear), ou substitua o placeholder pela fonte esperada; em qualquer variante, o diretório -i guarda o corpus de entrada e saída da evolução.

## Exemplo
Um programa de leitura binária com fopen(argv[1], "rb") encaixa exatamente no exemplo do README; o -i do input_dir pode começar vazio conforme a outra feature listada.

## Limites e trade-offs
A nota cobre o contrato de arquivo; o modo persistente (-P) descrito na mesma seção não usa o placeholder porque lê pela API in-process — não confunda os dois contratos de entrada.

## Como verificar
A linha do comando e a nota do placeholder são texto literal da seção Run Fuzzer do README oficial.
